## ⚠️ CI is green on less than you think

Nine test files need the 86 MB Scryfall card database, are written with
`describe.skipIf`, and therefore **skip on a machine without it, leaving the run
green.** CI holds types, build, source integrity, the conformance corpus, the
unit suite and the 500-seed fuzz gate. It does **not** hold §6 gate 1's database
half or gate 5 (the coverage accounting) — those run locally:

```
node scripts/cardgen/verify.cjs --full
```

That command, green, is what must be true before a batch lands. `AGENTS.md`'s
own §8 amendment records this rather than pretending otherwise.

## The loop

**The loop is PROVEN — M6.4a ran it end to end** (D158): eight scripts landed,
`verify.cjs --full` green, all five gates. Batches can scale now, but
⚠️ **classify every selected card against what the engine CONSULTS before
drafting it** — `select.cjs` emits every sole-need-`scriptable` card, and a
card whose only text is an activated ability is unlandable until the
`ActivatedDef` seam is built (D158's headline reportable; it cost 4 of the
first batch's 12).

```bash
node scripts/cardgen/select.cjs 25
```

Then, per card in `scripts/cardgen/batch.json`:

1. Read the card's **real oracle text** from the local database —
   `node electron/cardsvc-worker.cjs --query "<name>"`. Never a paraphrase, never
   from memory. This is D15b's rule and it has caught real drift.
2. Write `src/engine/scripts/cards/<moduleName>.ts`, exporting one
   `<MODULE_NAME>_SCRIPT`.
3. Write its test beside it, asserting on **EVENTS** rather than final state where
   possible.
4. Add the card to `fuzz.node.test.ts`'s `SCRIPTS` **and** its `DECK`.

```bash
node scripts/cardgen/land.cjs <moduleName>
node scripts/cardgen/verify.cjs --full
```

**Every landed card owes, in the same commit:** its `tier3.ts` note silent,
`engineComplete` accepting it, a place in the fuzz pool, and its tests. All four
are enforced by tests rather than by convention — `shippedScripts.node.test.ts`
and `fuzz.node.test.ts` between them.

## Non-negotiable constraints

- ⚠️⚠️ **Never use `git stash` or `git restore`.** The tree carries ~90 files of
  uncommitted work sitting on an old HEAD. Undo by editing, or by string surgery
  against a verified marker.
- ⚠️ **The generator may never touch `src/engine/`** outside `scripts/cards/` and
  the one `SHIPPED_SCRIPTS` line that imports from it. Primitives are hand-written
  reviewed work — that is where correctness for *every* card is decided, and a
  generated change to a primitive is a change to every card at once.
- **Scripts return EVENTS.** They are never handed a mutation API. `ctx.random` is
  a seeded scratch RNG threaded through the log, so a coin-flip card replays
  bit-exactly.
- **A script that cannot be verified is not landed.** No exceptions, no "mostly
  works" tier.
- **Never half-execute** (D90). A card the parser understands only in part must
  not run its understood half silently — that is the one outcome worse than not
  running it at all.
- **An unenforced category must be SAID** (D122/D124). Silence in this app means
  "handled"; 16,020 cards once said nothing at all.
- `src/engine/` is pure and deterministic: no React/Electron/Node/zustand, no
  `Date.now`/`Math.random`/`performance.now`. `src/bot/` additionally may not
  import a `GameState`-taking engine module or read `process.env`.
- **Offline-first is absolute.** Approved exceptions are listed in `AGENTS.md`.
  ⚠️ §7 names popularity data as an internet dependency — **stop and ask the user
  before fetching any.**

## Traps this repo has already paid for

Each of these cost real debugging time. They are here so you do not buy them
again.

- **`preview_start` does not work with these Electron apps.** Drive the renderer
  with `npx electron . --dev --remote-debugging-port=9223
  --disable-backgrounding-occluded-windows --disable-renderer-backgrounding`,
  then `node scripts/cdp.cjs "expression"`.
- **`window.__crt.engine.view()` lags the engine by one animation group** (D137,
  D146). It catches up only while the game is FLOWING; at the moment it stops it
  stays wrong. Assert off `submit()` results or the DOM.
- **Never run the batteries and the 500-seed gate at the same time, and never
  read a wall-clock number off a loaded machine** (D106). Three phantom
  regressions in this project, one of which triggered a four-hour hunt.
- ⚠️ **Patch scripts: write them to a FILE and run `node <file>`.** The shell eats
  backslashes inside `node -e`; that is how three regexes were written with a
  literal BACKSPACE instead of `\b` and **silently disabled three architectural
  guards for twenty-four decisions** (D153, D154). The repo is CRLF and some files
  carry mixed endings — normalise before anchoring.
- **No backticks inside a template literal** in `battery-anim.cjs`.
- **A "same multiset of lines" check does not prove a document reorder was safe**
  — every wrong arrangement is also a permutation (D157's correction).
- **The battery's step name is `precombatMain`, not `main`.**
- **`[data-instance-id]`, not the `[data-hand-instance]` slot wrapper**, and
  passing priority through a hotseat moves the viewer (D119, D145).
- **A prompt's ANSWERERS and its CONTROL are separate work** (D143). "The bot,
  the fuzzer and the net driver can answer it" reads exactly like "it is
  finished", and has twice not been.

## Open reportables you inherit

0. ⚠️⚠️ **`select.cjs` EMITS SPELLS THE PIPELINE CANNOT LAND** (D160). A spell
   executes through the effect vocabulary or not at all — `CardScript` has no
   spell seam — yet vocabulary-refused instants/sorceries are sole-need
   `scriptable` and re-appear in EVERY batch (`Aliban's Tower` is the first).
   Decide before the next batch: filter spells out of the selection, or queue
   them for vocabulary work. Also from D160: a script cannot raise a PROMPT
   from `resolve` (blocks the `Abyssal Horror` class), and the "modified"
   predicate awaits its own decision.
1. ⚠️ **The ~800 def-gated sacrifice-self cards are the widest seam open**
   (D159). `Sacrifice this <type>` is a chargeable price now, offered only
   when the game's registry carries the `ActivatedDef` — so each of those
   cards is ONE DEF away from executing, on machinery two landed cards
   already prove. A general sacrifice cost ("Sacrifice a creature") is a
   CHOOSER the activation stage does not have, and stays unpaid.
2. **`ctx.random` is a STUB at the (single, since D159) `ScriptCtx`
   construction site** (`below: () => 0`, `shuffled: (xs) => xs`) while
   `api.ts`'s header promises a seeded scratch RNG threaded through the log.
   No script that needs randomness may ship until it is wired.
3. **Targeting aims with the FRONT face's specs.** `beginAim` calls
   `session.targetSpecsFor(card)` with no face index, so a modal-DFC back face
   that targets cannot be cast through the UI. It fails **safe** — the host
   validates against the real face (D139) and rejects — and the fix is one
   parameter. Affects the subset of the 38 spell-back-face MDFCs that target.
4. **`collectTriggers` scans every card id per (event × def).** Fine at
   382.8 s with 22 defs (D159); the first suspect when the library grows. A
   per-oracle-id source index preserves iteration order bit-for-bit — build it
   measured, on an idle machine (D106).
5. **Computed life costs beyond War Room's exact phrase stay unpaid** — each
   new phrase is its own D90-anchored recognition with its own computation
   (D159's `lifeCostCommanderColors` is the template).
   ⚠️ Standing review rule from D158/D159: a `TriggerDef.abilityId` matching
   `/^a\d+$/` collides with the parsed-activated `abilityRef` namespace.
