## ⚠️ CI is green on less than you think

Nine test files need the 86 MB Scryfall card database, are written with
`describe.skipIf`, and therefore **skip on a machine without it, leaving the run
green.** CI holds types, build, source integrity, the conformance corpus, the
unit suite and the 500-seed fuzz gate. It does **not** hold §6 gate 1's database
half or gate 5 (the coverage accounting) — those run locally:

```
node scripts/cardgen/verify.cjs --full
```

That command, green, is what must be true before a batch lands. `AGENTS.md`'s
own §8 amendment records this rather than pretending otherwise.

## The loop

**The loop is PROVEN — M6.4a ran it end to end** (D158): eight scripts landed,
`verify.cjs --full` green, all five gates. Batches can scale now, but
⚠️ **classify every selected card against what the engine CONSULTS before
drafting it** — `select.cjs` emits every sole-need-`scriptable` card, and a
card whose only text is an activated ability is unlandable until the
`ActivatedDef` seam is built (D158's headline reportable; it cost 4 of the
first batch's 12).

```bash
node scripts/cardgen/select.cjs 25
```

Then, per card in `scripts/cardgen/batch.json`:

1. Read the card's **real oracle text** from the local database —
   `node electron/cardsvc-worker.cjs --query "<name>"`. Never a paraphrase, never
   from memory. This is D15b's rule and it has caught real drift.
2. Write `src/engine/scripts/cards/<moduleName>.ts`, exporting one
   `<MODULE_NAME>_SCRIPT`.
3. Write its test beside it, asserting on **EVENTS** rather than final state where
   possible.
4. Add the card to `fuzz.node.test.ts`'s `SCRIPTS` **and** its `DECK`.

```bash
node scripts/cardgen/land.cjs <moduleName>
node scripts/cardgen/verify.cjs --full
```

**Every landed card owes, in the same commit:** its `tier3.ts` note silent,
`engineComplete` accepting it, a place in the fuzz pool, and its tests. All four
are enforced by tests rather than by convention — `shippedScripts.node.test.ts`
and `fuzz.node.test.ts` between them.

## Non-negotiable constraints

- ⚠️⚠️ **Never use `git stash` or `git restore`.** The tree carries ~90 files of
  uncommitted work sitting on an old HEAD. Undo by editing, or by string surgery
  against a verified marker.
- ⚠️ **The generator may never touch `src/engine/`** outside `scripts/cards/` and
  the one `SHIPPED_SCRIPTS` line that imports from it. Primitives are hand-written
  reviewed work — that is where correctness for *every* card is decided, and a
  generated change to a primitive is a change to every card at once.
- **Scripts return EVENTS.** They are never handed a mutation API. `ctx.random` is
  a seeded scratch RNG threaded through the log, so a coin-flip card replays
  bit-exactly.
- **A script that cannot be verified is not landed.** No exceptions, no "mostly
  works" tier.
- **Never half-execute** (D90). A card the parser understands only in part must
  not run its understood half silently — that is the one outcome worse than not
  running it at all.
- **An unenforced category must be SAID** (D122/D124). Silence in this app means
  "handled"; 16,020 cards once said nothing at all.
- `src/engine/` is pure and deterministic: no React/Electron/Node/zustand, no
  `Date.now`/`Math.random`/`performance.now`. `src/bot/` additionally may not
  import a `GameState`-taking engine module or read `process.env`.
- **Offline-first is absolute.** Approved exceptions are listed in `AGENTS.md`.
  ⚠️ §7 names popularity data as an internet dependency — **stop and ask the user
  before fetching any.**

## Traps this repo has already paid for

Each of these cost real debugging time. They are here so you do not buy them
again.

- **`preview_start` does not work with these Electron apps.** Drive the renderer
  with `npx electron . --dev --remote-debugging-port=9223
  --disable-backgrounding-occluded-windows --disable-renderer-backgrounding`,
  then `node scripts/cdp.cjs "expression"`.
- **`window.__crt.engine.view()` lags the engine by one animation group** (D137,
  D146). It catches up only while the game is FLOWING; at the moment it stops it
  stays wrong. Assert off `submit()` results or the DOM.
- **Never run the batteries and the 500-seed gate at the same time, and never
  read a wall-clock number off a loaded machine** (D106). Three phantom
  regressions in this project, one of which triggered a four-hour hunt.
- ⚠️ **Patch scripts: write them to a FILE and run `node <file>`.** The shell eats
  backslashes inside `node -e`; that is how three regexes were written with a
  literal BACKSPACE instead of `\b` and **silently disabled three architectural
  guards for twenty-four decisions** (D153, D154). The repo is CRLF and some files
  carry mixed endings — normalise before anchoring.
- **No backticks inside a template literal** in `battery-anim.cjs`.
- **A "same multiset of lines" check does not prove a document reorder was safe**
  — every wrong arrangement is also a permutation (D157's correction).
- **The battery's step name is `precombatMain`, not `main`.**
- **`[data-instance-id]`, not the `[data-hand-instance]` slot wrapper**, and
  passing priority through a hotseat moves the viewer (D119, D145).
- **A prompt's ANSWERERS and its CONTROL are separate work** (D143). "The bot,
  the fuzzer and the net driver can answer it" reads exactly like "it is
  finished", and has twice not been.
- **A GATE THAT HAS ONLY EVER RUN WITH A SEAM SWITCHED OFF HAS NOT TESTED THE
  SEAM** (D368). A walk gated on `grantIndex.size > 0` costs nothing for
  exactly as long as no shipped script carries a `gt` def - so the decision
  that ships the FIRST one is the first gate that can see it, and D368 paid
  for it with a bot suite at 437.9 s and 5 of 6 failing. When a new walk
  joins an existing bus, give it the gates its neighbours already have (a
  per-event-KIND index, D162; a present-def memo, D168) rather than one
  emptiness check.
- **A HEREDOC THROUGH THIS HARNESS HALVES BACKSLASHES** (D369). A doubled
  backslash arrives as one and a backslash-b arrives as a literal BACKSPACE -
  invariant 14 in a patch script rather than a regex - and one D369 applier
  mangled a type import that way before `tsc` caught it. An applier never
  spells a backslash: it writes the currency sign and `patchlib.cjs`
  substitutes `String.fromCharCode(92)` at runtime. A single Bash command
  past ~100 lines is TRUNCATED besides (`unexpected EOF`) - split payloads
  into part files and concatenate them.
- **`advanceUntil` ANSWERS EVERY PROMPT IT PASSES, and `settle` IS an
  `advanceUntil`** (D370). A fire that ends in a settle answers its own
  question - the harness `simplestAnswer` declines - unless the settle`s own
  predicate already holds the moment the prompt goes up. D370's sacrifice rows
  passed because it did (the ability had left the stack) and its counter rows
  went red because it did not (the opponent`s spell was still on it). A
  scaffold that waits after raising a prompt waits for the PROMPT OR the quiet
  board, never for the quiet board alone.
- **A fixture a generator DERIVES is in no names list** (D370). A wave adds its
  own card names and its carried `helpers.json`; a cost fixture the row maker
  derived (D347) is in neither, and the suite says so only at run time. Read
  every name a generated suite puts or deals against the fixture WANTED list
  before the port.
- **A GRANT IS NOT ALWAYS A KEYWORD - the derive keeps THREE carriers apart**
  (D371): a keyword on `chars.keywords` (a Set), a landwalk TYPE on
  `chars.landwalk` (a string[] `canBlock` reads, CR 702.13) and a protection
  QUALITY on `chars.protection` (D356 gave it a structure). A reader, a guard
  or an emitter that knows only the first is silently wrong for the other two:
  the row maker's own `hasGrant` asked whether the keyword list was non-empty
  and emitted NOTHING for Goblin King, whose whole grant is mountainwalk.
- **THE PROBE AND THE CLASSIFIER MUST AGREE, and the probe is the one that
  lies** (D371). A candidate probe reads a scope head with a regex of its own
  where the classifier reads it with `staticRowShape`, so a widening applied
  to one and not the other leaves cards the pool OFFERS and the probe calls
  "not candidates" - which reads exactly like a missing card rather than like
  two readers disagreeing. Widen both, in the same pass.
- **THE DISCLOSURE EXAMPLE THAT KEEPS GOING SILENT** (D371). `tier3.test.ts`
  proves that a static the engine does not run is SAID even when the keyword
  it grants is enforced, and it has lost every example it has had to the
  engine growing - Avacyn (D300), Emblem of the Warmind (D324), Akromas
  Memorial (D371). Replace it with a grant the row grammar CANNOT express,
  never one it merely has not expressed yet.
- **A MANA ABILITY IS NOT A DEF** (D372, CR 605). It never uses the stack, so
  the engine carries it as the derived LIST `chars.producesMana` - what

  one is therefore a list entry `pushGrantedMana` appends at derive time with
  `abilityIndex = producesMana.length`, never a `<provider>#g<n>` ref, and a
  reader that routed it through `activatedDefFor` would half-run it (D90).
- **TWO GRANTS ON ONE PERMANENT ARE TWO PRODUCTIONS** (D372). Metallic Sliver
  under Cryptolith Rite and Basal Sliver carries index 0 (auto-tappable) and
  index 1 (priced - D325 keeps the solver off it); the first draft of the
  seam test expected ONE and was the thing that was wrong. Assert the list,
  never its length.
- **A DOUBLED BACKSLASH HALVES IN A MEASUREMENT SCRIPT TOO** (D372). The
  row-kind count read 41 because an escaped digit class arrived as a bare
  letter inside a template literal; `[0-9]+` gave the honest 49. Every script
  that passes through the harness spells no backslash, not only an applier -
  and a shard leg's `CRT_FUZZ_OUT` is a FILE path, not a directory (EISDIR

- **THE SELF WORD IS NOT THE SELF SUBJECT** (D373). Twice now a decision has
  predicted that a quoted payload needs its self word NORMALISED and been
  wrong: `damage` has always read "This creature deals" as its source, and
  `selfRef` has always spelled a card own name `~`. What a payload like
  "This creature gets +1/+0 until end of turn." needs is an effect whose
  SUBJECT is the resolving object own source, which is a parser rule AND an
  aim in `effects.ts` - measure the vocabulary with the real parser before
  calling a payload family a wave.
- **`it` IS NEVER A PARSER SUBJECT** (D373). On a spell "it" is the PREVIOUS
  sentence target ("Destroy target creature. It can't be regenerated.",
  "... Untap it."), so a rule admitting it reads that sentence for the spell
  itself - a whole card going `auto` over a clause aimed at the wrong thing.
  A QUOTED body "it" IS its recipient, so the rewrite belongs in
  `scripts/vocabulary.ts`, where the text is KNOWN to be a quoted body.
- **A HEAD LIBRARY IS A TAIL; A FILTER IS A MECHANISM** (D374). 109 head
  texts the library did not hold were 1.54 cards each - a tail no list of
  entries finishes - and by BASE EVENT they collapsed to seven. Read a head
  the library does not hold as a BASE head plus a CLOSED filter on its
  subject, and keep the BASE head NAME: the generator keys a dozen lists on
  it, and a filter that narrows an existing name inherits all of them.
- **PRICE A BUCKET WITH A THROWAWAY THAT CARRIES ON** (D352, D374). The row
  maker stops at the first blocker, so `trigger head not in the library: 168`
  says nothing about how many cards the head is the ONLY blocker for. A
  throwaway copy that accepts any head answered it: rows 171, unrowable 53.
- **THE FIXTURE A GENERATOR DERIVES IS IN NO NAMES LIST** (D347, D370, D374).
  A filtered head fires only for a card the filter admits, so the suite deals
  a DERIVED one - and it is in neither the wave own names nor helpers.json.
  The port collects them AND sweeps every name every generated suite deals
  against WANTED before it runs.
- **A GENERATED MATCHER MAY READ NEITHER PARAMETER** (D374). A filter naming
  neither the source nor its controller emits a body mentioning neither `ctx`
  nor `self`, and an unused parameter is a `tsc` error: name the parameters

- **THE FIXTURE TEST PINS THE TOKEN COUNT BESIDE THE TOTAL** (D374). The
  port sed repins only the total, so a wave with a new token pin must move
  the token count too.
- **A SEAM THE ENGINE ALREADY HAS CAN BE REFUSED BY THE SUITE** (D375). Ten

- **A SHIELD ASSERTED ALONE IS HALF THE RULE** (D375). Asserting that a
  regeneration shield exists proves the ability resolved and nothing about
  what a shield IS. Destroy the shielded permanent and assert it SURVIVED,
  tapped and undamaged, with the shield spent - and pick the killer from what

- **A BLANKET GUARD OUTLIVES ITS REASON** (D375). The fixture reader refused

- **A FILTER NARROWS A BASE AND CANNOT INVENT ONE** (D376). When the filtered

- **A BLOCK NAMES TWO CREATURES** (D376). The head is about the row own and

- **A FIXTURE WITH A JOB TO DO IS NOT THE PLAINEST CARD** (D376). A block

  defender - and never a LAND creature, because Dryad Arbor prints nothing,

- **A DERIVED FIXTURE MUST RIDE THE ABILITY** (D376). The row maker carried

- **A REQUIRED FIELD HAS A BOUNDARY, AND IT IS THE DOWNSTREAM COUNT** (D377).

  a `CardsMoved` and none of them is a sacrifice. Then the honest instrument
  is a test that DRIVES every emitter plus a canary with a floor - and say so
  where the field is declared, or the next reader will think the rule lapsed.
- **A CANARY IS NOT ALWAYS THE HASH** (D377). D364 added one because
  `poolSnow` is in the state hash and 500 equal replays would have proved
  nothing about an empty field. `CardMove.reason` never reaches `GameState`
  at all, so the hash cannot vouch for it in either direction: what the floors
  prove is that REAL GAMES produce the values, which is a different claim and
  the only one available.
- **A HEAD IS ONLY LANDABLE IF A SUITE CAN FIRE IT** (D377). Read the printed
  head, then ask what one submit would make the engine do it. Every sacrifice
  in this engine is a cost behind a def gate except a mana ability whose price
  is the permanent own sacrifice, which needs no script at all - so that is
  the fixture the derivation looks for, and a subject no such card satisfies
  is refused BY NAME rather than tested on something the suite cannot spend.
- **A ROW FIRES ITS OWN HEAD** (D377). A card that watches for a sacrifice and
  also has an activated ability that sacrifices does BOTH in that ability own
  test, and the baseline is what is wrong. Give the head contribution to the
  PAYING ability rather than widening the assert by hand.
- **A COMMENT IS AN EDIT** (D377). The self-audit corrected a figure inside a
  comment in `src/engine/types/events.ts` while the gate unit suite was
  running. Nothing behavioural moved and no assertion could have read it - and
  a gate log is a statement about a TREE, so the gate was stopped and restarted
  from the top. Twelve minutes is the whole cost of keeping a gate honest.
- **A CHECK WHOSE OUTPUT YOU PIPE CANNOT FAIL YOUR SCRIPT** (D377). The
  close-out ran `npm run build`, the probe and the battery through `| tail -3`,
  so `set -e` was reading the exit code of `tail`. The battery went red AFTER
  the push. Read `PIPESTATUS[0]`, or write a log and abort on a non-zero exit.
- **RENAME THE TEST, NEVER THE CHECK** (D377, and D144 and D147 before it). The
  battery greps `src/` for the word prompt followed by a bracket, to catch a
  `window.prompt` call that throws in Electron. Three test NAMES have tripped it
  now. It is the check working.
- **A ZONE THAT ANSWERS THE QUESTION NEEDS NO SEAM** (D378). D377 had to build
  `CardMove.reason` because a sacrifice and a discard are invisible in the zones.
  A card LEAVING a graveyard says so in its own `from` and a card PUT INTO one in
  its own `to`, so both bases are a head regex and a matcher with nothing under
  `src/engine/` moved. Ask what the EVENT already says before designing a field.
- **A CARD IN A GRAVEYARD HAS NO DERIVATION** (D378, and D171 before it). Read
  its type off the ORACLE FACE, and narrow the filter to what an oracle face can
  answer - card types and subtypes - rather than reading `derive` for a permanent
  that is not there. And a BARE subject needs no oracle read at all: emitting one
  and then returning true leaves a binding nothing uses, which is a `tsc` error.
- **A DERIVE SCRIPT IS EXEMPT FROM ITS OWN RENAME** (D378, D354 verbatim). The
  sed that produced `derive378.cjs` rewrote its own `.split(gen77-)` FROM side, so
  it no longer quoted what it was meant to find and every internal require in the
  derived chain stayed one decision behind.
- **A HEAD REACHED BY DROPPING A CHECK MUST BE PROVEN ON SOMETHING ELSE** (D379).
  The four bases this decision opened are the library head with its `=== self`
  test removed, so a suite that fires the trigger on the row own card passes with
  the test still in place - D128 green tick over nothing, in the one shape a
  widening can take. Fire it on a FIXTURE, from the OTHER seat where the printed
  line says any player, and on the exit no narrower head already catches.
- **A FILTERED HEAD KEEPS THE BASE NAME, SO EVERY LIST KEYED ON THAT NAME MUST
  ASK WHETHER IT IS FILTERED** (D379). That is D374 whole point and its cost: the
  board adjustment claimed the row own card had left, the cleanup target sat on
  the turn the fire itself ends on, and the untap hand and library adjustments
  belong to the SELF head alone. Sweep the trigger name with a COUNT (three sites
  for the untap, where an applier anchor found two).
- **RECOGNISE ON THE SCRUB MASK, CUT FROM THE RAW LINE** (D380, and D366 before
  it). The compound splitter finds its joining word on a mask that blanks every
  quoted span IN PLACE with spaces of the same length, so an offset found there
  still points into the raw text. A quoted ability carrying the word `or` would
  otherwise be split down the middle - and the mask is what proves it is not.
- **A PRONOUN BELONGS WHERE BOTH HALVES ARE IN HAND** (D380). `it` in the second
  half of a compound names whatever the FIRST half was about, and the row maker
  own rule is that `it` names this permanent only under a head about this
  permanent. Resolving it in the SPLITTER keeps the head library from learning a
  word whose meaning depends on a line it cannot see.
- **TWO DEFS ON ONE CARD NEED TWO IDS AND TWO TITLES** (D380). A compound can put
  the same head on one card twice (Ultron Auxiliary watches its own graveyard
  from two zones): two defs sharing a ref is two abilities the engine cannot tell
  apart, and two tests sharing a title is a failure that cannot say which half
  broke. Disambiguate ONLY when it must, so every id shipped before stays
  byte-identical.
- **A MODIFIER ADDED TO ONE PUSH IS DROPPED BY EVERY OTHER** (D381). The three
  PAIR heads (attacksOrBlocks, isDealtDamage, entersOrAttacks) push their two
  abilities and continue BEFORE the general push at the foot of the trigger
  branch, so a condition added to that one alone vanishes for them - and a card
  that does MORE than it says is the one direction D90 forbids outright. Put
  every modifier in ONE object and spread it into EVERY push.
- **A RULE THE ENGINE CANNOT REACH FROM ITS EMITTERS BELONGS IN THE FUNNEL**
  (D382). Hundreds of shipped modules build a `DamageDealt` themselves, so a
  prevention shield consulted inside `effects.ts` would be skipped by every one
  of them. CR 615.1 says a prevention effect IS a replacement effect, and the
  funnel is the one place every event passes through - correct by construction
  rather than by a list of call sites kept in step. And walk the WHOLE BATCH:
  `applyReplacements` sees one body at a time against a state that does not
  advance between them, so two damage events would each spend the same shield.
- **A BLANKET GUARD OUTLIVES ITS REASON** (D382, D375). The clause fixture picker
  refused any clause whose kinds included `battle`, and `any target` is
  [creature, player, planeswalker, battle] - so every prevention row was refused
  for a clause a CREATURE serves perfectly. Narrow it to the case that genuinely
  has no fixture; read the refusal STRING, never the bucket label (D365).
- **AN APPLIER MUST MATCH THE FILE ITS OWN LINE ENDINGS** (D382). A heredoc
  payload is LF and `triggers.ts` is CRLF, so the anchor matched NOTHING. The
  counted guard caught it - which is the difference from D258, where a silent
  `String.replace` over a CRLF file reported success - but catching it every
  time is not handling it: convert the payload to the FILE`s own line ending.
- **A SWEEP CATCHES EVERY CREATURE ON THE BOARD, INCLUDING THE ONES THE ARM
  PUT THERE** (D383). A row whose card is a creature is inside its own `each
  creature` scope, and so are the five Goblins its tap cost just tapped - both
  read a card in the GRAVEYARD with its battlefield fields cleared, so the cost
  mark reads false. Ask the scope arithmetic of EVERY subject the suite asserts
  on, from ONE reader, or a fix reaches one and misses the other.
- **INVARIANT 14 BITES A MEASUREMENT SCRIPT TOO** (D383). A doubled backslash
  halves in a heredoc, and inside `new RegExp(string)` the JS string escape then
  eats what is left: a digit class became the letter `d` and the sweep measured
  1 card where the honest figure is 12. A seam priced at a twelfth of its worth
  would not have been built at all - use regex LITERALS and explicit ranges.
- **A WAITER WHOSE PREDICATE CANNOT MATCH IS AN INFINITE SPIN** (D383). Three
  background waiters were found still polling after SIX HOURS: two were
  `until grep -qE ...` loops over a log whose wording never contained any
  alternative (a battery that prints `Failures:` matches neither `FAIL` nor
  `failed`), and the third had CRASHED hours earlier and hung on a trailing
  `node -c` - which, with no file argument, reads STDIN and never returns. They
  were not idle: each spawned a `sleep` and a PowerShell every 15-20 s, on the
  machine, while a gate ran - which is the load D106/D255/D270 blame for
  spurious timeouts. Grep for a string the tool ACTUALLY prints, prefer a cheap
  log grep over a process poll, keep ONE waiter per thing, and use
  `node --check <file>`, never a bare `node -c`.
- **A DEF CLAIMS ONE LINE, SO COUNT THE PRINTED ONES** (D384). `lineClaims`
  matches a def is text against ONE unaccounted line (D158), so a def whose
  text is the WHOLE printed face silences nothing - and the row maker is
  multi-line flag was counted off the row is LEFTOVER lines, which are what the
  accounting has not claimed rather than what the card prints. Five modules
  landed, registered, typechecked and passed their own suites while leaving
  every one of their cards INCOMPLETE; `shippedScripts.node.test.ts` named all
  five, and nothing else noticed. Count PRINTED lines.
- **`settle` DOES NOT ANSWER A PROMPT ITS PREDICATE ALREADY SATISFIES** (D384).
  A staged activation puts nothing on the stack until its targets are chosen,
  so an empty stack with no pending triggers holds WHILE a `chooseTargets`
  awaiting is up: `settle` returns at once, the answer never arrives and the
  cost is never charged (the log ends `CastBegan, AwaitingSet`). D370 is trap
  from the other side - there a settle ATE a prompt by answering it, here one
  walks past by not trying. A scaffold that waits after raising a prompt waits
  for the prompt to be GONE (`awaiting === null`), never for the quiet board.
- **WHERE A COST MARK CAN BE READ DEPENDS ON WHETHER THE PAYLOAD TARGETS**
  (D384). CR 601.2 charges a staged activation on the ANSWER (D169), so a cost
  mark taken before the targets are declared reads the board as it was; an
  untargeted ability is charged at the submit and the same read is correct.
  One rule, two placements - decide it from the PAYLOAD, never from the cost.
- **A BY-NAME SACRIFICE IS NOT A COST, AND THE CAPITAL LETTER IS THE TELL**
  (D384, D377). `Sacrifice Ninja is Kunai` names the CARD, so the carrier is own
  guard throws at MODULE LOAD rather than claim it - refuse the row at the
  generator or the whole batch fails to import. ⚠️ A guard reading `Sacrifice`
  plus a word is too broad: `Sacrifice two other creatures` is a COUNTED
  sacrifice D353 charges. The discriminator is the CAPITAL letter.
- **A CONDITION IS PROVEN BY THE FIRE THAT DOES NOT HAPPEN** (D381). Firing once
  with a condition MET proves the ability resolves and says nothing about the
  condition. Fire twice - broken, then met - with the stage-one check as a THROW
  inside the arm, where the mark is in hand; and refuse a payload the arm cannot
  read rather than widening the read.
- **A FIXTURE DERIVATION MUST ANSWER EVERY FIELD THE FILTER CARRIES** (D381). One
  that ignores a field hands the suite a card that does not satisfy it - a
  while-you-control-a-TOKEN condition was given a Badlands. D350 rule: a filter
  no fixture satisfies REFUSES the row, and is never given one that ignores it.
- **A NAME THAT IS A RULES WORD** (D373). `selfRef` spells a card own name
  `~` before any rule runs, so the card named Regenerate arrives as "~ target
  creature." and reads as nothing. Ledger it under THAT, not under the
  mechanic it appears to be waiting for.
- **THE UNTAP SYMBOL IS A COST AND ITS OFFER IS GATED ON BEING TAPPED**
  (D373). `legal.ts` skips a `requiresUntap` ability while the permanent is
  UNTAPPED, so a `{Q}` row is not offered at all until the scaffold taps the
  recipient - which is also the only way an untap PAYLOAD is observable
  (D128). The generator taps first in both cases.

## Open reportables you inherit

   when the game's registry carries the `ActivatedDef` — so each of those
   cards is ONE DEF away from executing, on machinery two landed cards
   already prove. A general sacrifice cost ("Sacrifice a creature") is a
   CHOOSER the activation stage does not have, and stays unpaid.

   No script that needs randomness may ship until it is wired.

   `session.targetSpecsFor(card)` with no face index, so a modal-DFC back face

   parameter. Affects the subset of the 38 spell-back-face MDFCs that target.

Commander-legal cards now execute completely, up from Y"* — never as a count of
